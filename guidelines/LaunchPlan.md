# 플라비 · 출시까지의 결정과 계획 (2026-10-14)

사업자등록·법률 확인·카카오 채널·PG·본인인증 업체 상담은 **뒤로 미룸**. 그 전에 할 수 있는 것부터 결정하고 진행한다.

## 1. 정책 결정

### 상대 프로필 열람 기간 · V6-provision-01 (확정, 약관 반영 필요)

| 단계 | 열람 가능 기간 |
| --- | --- |
| 소개 | 정오 공개 ~ 다음 날 11:00 응답 마감 |
| 상호 선택 후 | 교류비 결제·합의 → 3일 교류 → DAY04 → 약속까지, 최대 약속일 다음 날 23:59 |
| 종료·중단·차단·탈퇴·안전 조치 | 즉시 닫힘 |
| 끝난 소개 다시 보기 | 없음 (보관함 없음) |
| 제공된 프로필 사본(버전 기록) | 종료 후 30일 뒤 삭제, 분쟁 증거만 분리 보존 |

- 이유: 응답 마감과 같은 기준이라 회원이 이해하기 쉽고, 연락처 표시 기간(만남 다음 날 23:59)과 끝이 맞는다. 끝난 상대를 계속 보지 못하게 해 사진 유출 위험을 줄인다.
- 이 결정으로 그동안 막혀 있던 ‘실제 소개 공개 예약’ 검사가 풀렸다(데모 기준).

### 운영 처리량 · V6-ops-01

| 항목 | 기준 (운영자 1명) |
| --- | --- |
| 신규 신청서 검토 | 하루 20건 (1건 약 10분) |
| 소개 준비 | 하루 10쌍 (1쌍 약 15~20분, 추천 보조 포함) |
| 베타 | 성별당 10명 (총 20명) |
| 운영자 1명이 함께 챙길 활동 회원 | 성별당 40명 (총 80명) — 기수(1기·2기) 개념은 없음 |
| 증원 신호 | 검토 대기가 3일치(60건)를 넘을 때 |

- 이유: 하루 3~4시간 운영으로 감당 가능한 양. 활동 회원 80명이면 하루 최대 10쌍(20명)이 소개받을 수 있어, 조건이 맞는 후보가 있다면 한 사람당 며칠에 한 번꼴로 소개가 가능하다.
- 관리자 대시보드 ‘오늘 운영 처리량’에서 확인. 회원 화면에는 예상 날짜·인원을 보여 주지 않는다.

### 문장 확정

- 운영진의 편지: 현재 문장으로 확정. 서명은 개인 이름 대신 **‘플라비 드림’**(브랜드의 목소리). 대표 이름을 넣고 싶으면 그때 교체.
- 두 사람의 이야기(해윤·서진): 현재 문장으로 확정. ‘가상의 이야기’ 표기와 ‘모든 소개가 이렇게 흘러가지는 않아요’ 안내 유지.
- 맺음말: ‘다음 이야기는, 준비된 날 정오에 시작돼요. — 플라비 드림’.

### 고객 문의 · V6-inquiry-01 (구현 완료)

- 공개 문의 페이지 `/contact` (푸터 ‘문의하기’), 관리자 ‘신고·안전’의 고객 문의함.
- 이메일·부를 이름(선택)·문의 내용, 개인정보 수집 동의 필수, 주민번호·카드번호 입력 차단.
- 접수 번호 + 이메일로 진행 상태·답변 확인. 보관: 답변 완료 후 3년(분쟁 기록) 초안.
- 내부 응대 목표: 평일 기준 2일 이내 첫 답변 (화면에는 약속하지 않음).

## 2. 서버 구축 결정

### 구성

| 역할 | 선택 | 이유 |
| --- | --- | --- |
| 화면 | 지금처럼 Vercel | 이미 배포 중, 그대로 사용 |
| 데이터베이스·로그인·파일·예약 작업 | **Supabase (서울 리전)** | 1인 개발에 맞음, DB 단계 권한(RLS)·파일 저장·예약 작업 내장, 국내 리전으로 개인정보 국외 이전 부담 줄임 |
| 정오 12:00 처리 | Supabase 예약 작업(pg_cron) → 서버 함수 | 매일 12:00 KST 실행, 같은 회원·날짜·종류 중복 방지 키 |
| 알림톡 + 문자 대체 | 솔라피 (사업자등록 후) | 알림톡 실패 시 문자 자동 대체 지원 |
| 결제 + 휴대폰 본인인증 | 포트원 (사업자등록 후) | 결제대행사와 본인인증을 한 곳에서 연동 |

비용 감: 개발 중 무료, 출시 시 Supabase 유료 플랜(월 약 25달러) + 알림톡·문자 건당 비용. 실제 단가는 계약 전 확인.

### 만드는 순서

진행 상황(2026-10-16): 1~4·6·7단계 서버와 화면 연결 완료(실제 서버 모드), 5단계(교류·약속·연락처)가 다음 차례. 반영 방법은 `ServerSetup.md`.

사업자 없이 할 수 있는 것부터:

1. 데이터베이스 설계, 로그인(개발 중에는 이메일 로그인), 관리자 역할 4종(Owner·운영·상담·정산)과 권한
2. 신청서·사진 실제 저장 (비공개 저장소, 위치정보 제거, 짧게 만료되는 사진 링크)
3. 관리자 검토·후보 추천·성비·처리량을 실제 데이터로
4. 정오 공개와 사이트 안 알림 (V6-provision-01 열람 기간 적용)
5. 교류(편지·첫 장면), 약속, 연락처 공개
6. 문의함·신고·노쇼·탈퇴 요청을 실제 데이터로
7. 삭제 예약 작업(7일·30일), 감사 기록 수정 불가 처리

사업자등록 이후:

8. 휴대폰 본인인증 (출시 전 필수로 전환)
9. 결제·환불 (요청 → 검토 → 실제 환불 분리 유지)
10. 알림톡 발송

## 3. 출시 준비 결정

- **도메인:** 후보 `beforeus.kr`, `beforeus.co.kr`, `before-us.kr`. 사용 가능 여부를 확인해 하나를 사서 Vercel에 연결한다(비용이 적어 미리 해 둬도 됨).
- **카카오 템플릿 심사:** 14종 중 출시 필수 8종 먼저. 오늘의 인연, 오늘은 소개가 없을 때, 서로 알아가고 싶다고 답했을 때, 이번 소개 마무리, 교류 시작, 만남 의사, 약속 확정, 신청서 검토 완료. 나머지는 출시 후.
- **베타 테스트:** 지인 중심 남녀 각 10명, 2주, 실제 결제 없이.
  - 확인할 것: 신청 완료율, 첫 소개까지 걸린 날, 상호 선택 비율, 3일 교류 완료율, 만남 의사, 만남 후 피드백, 문의 내용
  - 수치는 내부 판단용이며 홍보 문구로 쓰지 않는다
- **운영 매뉴얼 목차:**
  1. 신청서 검토 기준과 사진 보완 사유
  2. 한 쌍 고르기 체크리스트 (추천 보조 사용법 포함)
  3. 정오 운영 절차 (전날 준비 → 당일 확인 → 공개 후 문의)
  4. 문의·신고 응대 (평일 2일 이내 첫 답변, 안전 신고 우선)
  5. 늦은 취소·노쇼 확인과 이용 정지
  6. 환불 요청 처리
  7. 탈퇴·삭제 요청과 법정 보존 자료
  8. 사고 대응 (긴급 상황, 연락처 악용, 개인정보 유출 의심)
