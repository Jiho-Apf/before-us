# 프로젝트 내부 지침 — BEFORE US V6

## 29 — 공개 홈 감각 개선 (03번 공개 홈 방향 유지, 되돌릴 지점: git 태그 before-home-redesign)
- 첫 화면과 각 섹션 도입부는 감정적인 문장으로 시작한다. 운영 규칙과 ‘~하지 않습니다’ 안내는 지우지 않고 요금 섹션의 ‘분명히 해 두고 싶은 것들’과 FAQ로 옮겼다.
- 정오 시계는 ‘다음 정오까지’만 센다. 매일 소개가 온다는 표현을 쓰지 않고 ‘소개는 준비된 날, 정오 12시에 도착해요’를 함께 둔다.
- 두 점 모티프: 넓은 화면에서 첫 화면 이후 오른쪽에 두 점이 스크롤에 따라 가까워지고, 마지막 신청 영역에서 큰 두 점이 맞닿는다. 움직임은 스크롤 위치에만 연동하며 자동재생·무한 반복·3D 연출은 없다. 움직임 줄이기 설정이면 맞닿은 상태로 고정한다.
- 운영진의 편지는 ‘비포어스 드림’ 서명의 초안이다. 대표의 실제 경험·이름을 지어내지 않는다. DirectIntroduction은 편지 아래에 둔다.
- 편지·첫 장면 체험은 화면 메모리에서만 동작하고 어디에도 저장·전송하지 않는다. 상대 응답을 만들어 보여 주지 않는다.
- 질감은 보라·파랑 면의 옅은 종이결과 빛 번짐, 카드 hover 시 살짝 들림(200ms)까지만. Pretendard와 색 토큰은 그대로 쓴다.
- 2차(되돌릴 지점: before-home-round2): 시간대별 첫 화면 색·문구(아침·정오·오후·저녁·밤, 보라·파랑 범위 안, 검정·금색 금지, 실제 회원 활동을 지어내지 않는 문구), 섹션 번호 라벨 ‘(01) 한국어 — ENGLISH’, 세로쓰기 한 줄은 첫 화면 한 곳만, 마지막 장면에 편지형 맺음말·콜로폰.
- ‘두 사람의 이야기’(home-story.ts)는 가상의 이야기임을 제목과 설명에 밝힌다. 실제 사례·후기로 바꾸려면 당사자 동의와 별도 검토가 필요하다. 모든 소개가 이렇게 흘러가지 않는다는 안내를 함께 둔다.
- 오늘의 질문은 서울 날짜 기준으로 모두에게 같은 질문을 보여 주고, 지난 14일 질문만 넘겨 볼 수 있다. 내일 질문은 잠근다. 답은 저장·전송하지 않으며 다른 사람의 답을 보여 주지 않는다.
- ‘매일 정오’ 표현은 쓰지 않는다(국내 유사 서비스와 구분). ‘준비된 날, 정오’로 쓴다. 성공률·회원 수·후기·언론 로고·흐르는 글자 띠·커서 효과·자동 재생 소리·재화/게임 요소·배타적 말투는 넣지 않는다. 에세이 아카이브는 실제 글이 쌓인 뒤에만 연다.

## 28 — 회원 메시지 템플릿 V6-message-01 (16번의 정오 알림 원칙 유지)
- 관리자 알림(/admin/notifications)에서 메시지 템플릿 14종(소개·교류·약속·만남·신청·계정)을 관리한다. 로직은 message-templates.ts, 화면은 MessageCenter.tsx.
- 카카오 알림톡(정보성) 우선, 실패 시 문자 대체. 템플릿마다 알림톡 본문과 문자 대체 문구를 따로 두고, 문자 90바이트 초과는 장문(LMS) 경고를 띄운다.
- 허용 변수만 사용: 이름·링크·응답기한·결제기한·시작일·약속일시. 상대 이름·사진·연락처·편지·장소 원문은 메시지에 넣지 않고 홈페이지 링크로 안내한다. 광고 문구·원문 URL·전화번호·이메일은 저장을 막는다.
- 저장마다 새 버전과 수정 이유를 남기고 이전 버전으로 되돌릴 수 있다. 상태는 초안 → 검수 요청 준비 → 심사 중 → 승인/반려이며, 카카오 심사 결과는 대행사 화면 결과를 운영자가 수동 기록한다. 승인된 문구를 고치면 초안으로 돌아가 재심사가 필요하다.
- ‘오늘은 소개가 없을 때’ 안내는 대기 중 안내를 켠 회원에게만 보낸다(16번). 12:00 발송 미리보기는 공개 예약된 소개 회원 수와 대기 회원 최대 수만 보여 준다. 실제 발송·예약 작업·발송 결과는 미연결이다.

## 27 — 후보 추천 보조·성비·신뢰 장치 (상세: MatchingAssist.md)
- 후보 추천 1단계(V6-match-assist-01)는 규칙 기반 보조다. 필수 조건·차단·과거 상대·활동 상태·성비 대기·접수 전으로 먼저 제외하고, 양쪽이 직접 입력한 답변의 겹침만 이유로 쓴다. 모든 이유는 양쪽 원문 값을 근거로 인용한다. 사진·외적 취향·MBTI·체형·스타일·직업은 쓰지 않는다. 가중치는 정렬에만 쓰고 화면 DTO에 넣지 않는다. 실제 만남 가능 지역 밖 후보는 뒤로 보내고 표시한다. 최대 5명, 근거 없으면 추천하지 않으며 조건을 자동 완화하지 않는다.
- 추천은 운영진 최종 선택을 대신하지 않는다. ‘이 후보와 조건 비교’는 기존 비교·배정 차단 검사로만 연결하고, 추천 표시와 실제 선택(추천 목록 안/밖)을 기록한다. 공개 홈 DirectIntroduction에 보조 도구 사용과 사진·외모 미사용, 운영진 최종 결정을 고지한다. 외부 AI·서술형 요약은 서버·고지·동의 준비 전 사용하지 않는다.
- 성비(V6-balance-01): 접수된 활동 신청자(대기열 제외) 기준, 60% 초과 경보, 70% 이상이면 많은 쪽 성별의 새 신청을 거절하지 않고 ‘순차 검토 대기’로 둔다. 같은 지역·연령대 묶음도 10명 이상이면 따로 판단한다. 10명 미만은 판단 보류, 1~4명은 정확한 숫자를 보여 주지 않는다. 대기 해제는 오래 기다린 순서이며 해제 후 70%를 넘으면 운영자 사유가 필요하다. 대기 중 신청자는 추천·배정에서 제외한다. 회원에게는 인원·비율 없이 ‘순서대로 검토 중’만 안내한다. 성별 가격 차등은 하지 않는다.
- 본인·성인 인증은 가상 휴대폰 본인인증이다. 원본 이름·전화번호·생년월일은 저장하지 않고 만 나이·인증 시각·가상 중복 확인 키만 둔다. 인증 전에는 신청 접수를 막고, 만 19세 미만은 차단, 이전 이용 제한 계정과 같은 키는 배정 검사에 ‘재가입 확인 필요’로 표시한다. 실제 인증 업체·연계정보 대조는 미연결이다.
- 기혼·교제 확인: 기존 자기진술에 더해 ‘허위로 확인되면 이용 종료·상대 보호 조치’ 고지 확인(self.pledge)을 필수로 받는다. 미혼 인증이 아니다. 신고 유형 ‘기혼·교제 중 의심’과 ‘실제 만남 관련 문제’는 ‘우선 확인’ 우선도다.
- 첫 만남 안전 가이드와 만남 후 피드백은 최종 합의된 약속 아래에 둔다. 피드백은 약속 시작 60분 뒤부터 회원당 1회, 상대에게 전달하지 않고 운영진만 본다. ‘상대가 오지 않았어요’는 노쇼 신고로 안내하고, 안전 확인 요청은 신고(실제 만남 관련 문제)로 함께 접수한다.
- 투명한 대기 상태는 실제 기록이 있는 단계만 완료로 표시하며 예상 날짜·남은 인원을 만들지 않는다. 프로필 완성 코칭은 운영진이 참고하는 선택 항목만 안내하고, 비워도 신청은 그대로 진행된다고 명시한다.
- 상대 프로필 제공 기간은 아직 미정이다. `unresolvedPolicies.provisionPeriod`가 null인 동안 실제 공개 예약은 차단한다. (보유기간 초안 V6-privacy-01과 별개)

## 26 — 개인정보 보유·삭제·탈퇴 V6-privacy-01-draft (이전 ‘보유기간 미확정’ 문구보다 우선)
- 법률 검토 완료라고 표현하지 않는다. 정책 UI와 가상 데이터 상태만 구현하며 실제 삭제·백업 파기가 완료됐다고 말하지 않는다. 기준값은 config.ts `privacy`, 로직은 privacy-policy.ts, 화면은 PrivacyPanels.tsx(/profile, /demo/privacy, /admin/safety·settings)다. 상세는 PrivacyPolicy.md.
- 보유 초안: 계정·프로필·비공개 선호는 이용 중, 사진은 이용 중이며 삭제·탈퇴 후 활성 저장소 7일 이내 삭제, A/B 편지·공동 장면은 교류 종료 30일 뒤, 약속 날짜·시간·장소 상세는 약속일 후 90일, 상대 전화번호는 만남 당일 00:00~다음 날 23:59만 표시(contact-model에서 이후 번호 미제공), 관리자·접근 감사 로그 1년, 일반 백업 순환 최대 30일.
- 법정 보존: 계약·청약철회·결제·서비스 공급 5년, 소비자 불만·분쟁 3년, 표시·광고 6개월, 안전 신고 증거는 사건 종결 후 기본 3년, 법적 절차는 필요한 자료만 별도 보존 후 종료 시 파기 검토. 일반 프로필과 분리하며 재매칭·광고에 쓰지 않는다.
- 내 정보에서 ‘일시정지’(신규 소개만 중지, 기존 권리 보존)와 ‘회원 탈퇴’를 분리한다. 탈퇴 요청 즉시 상대 노출·신규 접근·미공개 연락처 예약·불필요한 알림을 멈추고, 일반 자료는 7일 이내 활성 시스템, 백업은 최대 30일 내 순차 삭제 예정으로 기록한다.
- 진행 중 소개·교류·약속은 탈퇴 전에 종료 내용을 보여 주고 환불·취소 요청 상태를 함께 만든다(진행 중 교류는 V6-conduct-01 본인 단순 변심 중단으로 기록). 탈퇴 자체를 불필요하게 막지 않는다. 자료 삭제 요청은 탈퇴가 아니다.
- 정정·삭제·처리정지 요청과 운영자 처리 결과를 기록한다. 처리할 수 없는 법정 보존정보는 사유와 보존기간을 안내하며, 법정 보존 항목이 있는 요청은 ‘전부 처리’로 기록할 수 없다. 결제 기록 정정은 원본을 바꾸지 않고 정정 사실을 별도 기록한다.
- 신고를 이유로 사진·편지 전체를 오래 보관하지 않는다. 분쟁에 필요한 항목만 최대 3개 증거로 분리하고 종결 후 3년을 산정한다.

## 25 — 교류 중단·약속 취소·노쇼·재이용 운영 기준 V6-conduct-01 (24번의 노쇼·재이용 미확정 문구보다 우선)
- 기존 A/B·약속·연락처 공개 로직과 V6-refund-01 DAY별 산정은 그대로 쓴다. 기준값은 config.ts `conduct`, 로직은 conduct-policy.ts, 화면은 ConductPolicy.tsx(/demo/conduct, /profile, /admin/safety)다. 상세는 ConductPolicy.md.
- 교류 중단: 본인 단순 변심은 미시작 DAY 금액만 환불, 실제 시작 후면 초기 소개 혜택 종료. 상대 미응답·중도 이탈·운영 문제는 피해자에게 미제공 DAY 환불 + 다음 소개비 5,000원 면제(운영 확인 후). 본인이 남긴 단순 변심 기록은 상대의 중도 이탈 피해를 즉시 인정한다. 안전·신고 사유 중단은 단순 변심으로 자동 판정하지 않고 운영 확인으로 보낸다.
- 약속 취소: 시작 24시간 이전은 일반 취소(재조율/종료 선택), 24시간 이내는 늦은 취소 기록. 늦은 취소 피해 상대가 교류를 종료하면 5,000원 면제. 응급·질병·사고·안전 사유는 운영자 확인 후 불이익 미적용. 시작 이후는 취소가 아니라 노쇼 확인 대상이다.
- 노쇼: 시작 30분 경과 + 사전 취소·연락 없음일 때만 신고. 자동 판정 없이 운영자 사실 확인. 확인 시 기본 14일 소개 이용 정지, 반복·고의성은 30일 이상/이용 종료 ‘검토 대상’ 표시만 하고 자동 적용하지 않는다. 피해자 5,000원 면제 + 우선 재소개. 노쇼만으로 정상 제공된 교류비 전체를 자동 환불하지 않는다.
- 재이용: 정상 종료 뒤 새 회차 소개비 5,000원, 새 상대 상호 선택 시 교류비 24,000원. 기존 프로필·사진·취향 재사용. 마지막 검토 후 90일 이상이거나 검토 기록이 없으면 사진·지역·직업·관계상태·선호 재확인(기록 없음을 90일 이내로 추정하지 않는다). 면제 대상은 새 회차에 한 번 적용한다.
- 상대에게 취소·노쇼·제재 사유를 자세히 공개하지 않는다. 모든 이용 제한은 관리자 기록·감사 로그와 재검토 경로(판단 대상자는 불리한 기록, 주장자는 불인정 결과에 1회)를 둔다. 감사 로그에는 사유 원문·연락처를 넣지 않는다.
- 운영 기준이며 실제 약관 법률 검토 완료가 아니다. 실제 정지 집행·환불 지급·서버 원장은 미연결 가상 데모다.

## 24 — 확정 결제·환불 운영 기준 (이전 환불 미확정 안내보다 우선)
- 신규 가상 구매에는 V6-refund-01 스냅샷을 적용한다. 기존 가격 5,000원+24,000원과 소개 흐름을 유지하며 과거 구매·동의·거래에 자동 소급하지 않는다. 과거 정책 원본이 없으면 개별 확인이고 무조건 환불 불가로 추정하지 않는다.
- 소개비는 실제 첫 후보 준비·참여·제공 범위 확인 후만 요청 가능하다. 첫 소개 확인하기 클릭만으로 개시하지 않고, 안내 확인 뒤 공개 허용 상대 프로필이 실제 보이는 화면에서 첫 제공 개시 시각/소개 ID를 한 번 기록한다. 실제 열람 전 취소는 전액, 개시 후 이미 제공된 서비스분 처리이되 오류·필수조건 위반 등 운영 귀책에는 전액이다. 귀책 확인/법정 권리 검토/환불 처리는 별도다.
- 활성 연속 30일 유효한 새 소개가 없으면 계속 이용 또는 5,000원 전액 환불 종료를 본인이 선택한다. 유효한 동시 공개 이벤트가 대기 기준을 갱신한다. 정지/철회/탈퇴 요청/차단은 연속 활성 대기에서 제외하며 기록 없는 기간은 추측하지 않는다. 계속 이용은 새 활성 대기 구간 선택이고 자동 만료/종료/새 청구가 아니다.
- 교류비는 DAY별 8,000원씩 3일의 가분적 서비스다. 실제 DAY01 콘텐츠 개시 전 24,000원, DAY01 후 DAY02 전 16,000원, DAY02 후 DAY03 전 8,000원, DAY03 후 미제공 DAY 환불 없음이다. 계획한 날짜·결제·합의·페이지 방문만으로 DAY 개시를 생성하지 않는다. 기존 실제 가상 개시 및 권한·해당 DAY 콘텐츠 이용 가능 게이트를 통과한 이벤트만 개시 기록으로 사용하며 미제출을 미제공과 동일시하지 않는다.
- 상호 선택 후 기본 결제 기한 24시간, 한쪽만 결제하고 상대 미결제면 결제자 전액/소개 권리 복원 대상이다. 양쪽 유효 승인 시각 이후 A/B·시작일 합의 기본 48시간, 양쪽 직접 동의 시 24시간 1회 연장이다. 양쪽 합의 완료와 실제 시작은 별도다. 끝내 실제 시작 안 되면 교류비 전액/소개 권리 유지다.
- 기한·산정·환불 요청·운영 검토·PG 실제 환불 완료를 분리한다. 요청 클릭이나 기한 도래로 환불 완료 시각/원장/승인/상대 동의/소개 종료를 생성하지 않는다. 소개 권리는 상호 선택·결제·합의만으로 소멸하지 않으며 미시작 교류 환불과 별도다. 실서비스 권리 복원·종료 및 지급 실행은 검증된 서버/PG 원장으로 해야 한다.
- 법정 청약철회 권리와 실제 약관 검토보다 불리한 자동 규칙을 만들지 않는다. 개시 후 소개비/운영 귀책 등은 운영 기준 계산과 법정·약관 권리 확인을 구분한다. 보유기간·재이용·노쇼 등 이번에 확정되지 않은 정책은 임의로 정하지 않는다.
- 실제 PG·서버 제공 이벤트·승인/환불 웹훅·예약/기한 처리·실제 권리 원장은 미연결이다. 모든 변경은 가상 상태·안내·데모 로직이며 실제 수집/과금/발송/환불/자동 공개/배포하지 않는다.

## 23 — 출시 전 통합 점검
- 기존 화면·가격·소개·A/B·약속·연락처 공개 로직을 재생성하지 않는다. 직접 실행 확인/코드 확인/데모/미구현/출시 전 정책 확정 필요를 구분해 보고한다.
- 공개 홈·진행 방식과 관리자 검토에서 동일한 운영진 최종 직접 선정 메시지와 ‘끌리는 사람을, 천천히 알아갑니다.’를 재사용한다.
- 기존 신고 접수에 노쇼와 약속 취소를 별도 유형으로 추가한다. 기존 연락처 악용 신고·차단/중단 경로를 유지한다. 접수는 실제 취소/자동 차단/환불 완료가 아니며 노쇼·취소·중단 대응 기준은 출시 전 확정/고지가 필요하다.
- 연락처 동의는 약속 ID만으로 재사용하지 않는다. 최신 약속 ID·버전·선택 일시가 결합된 agreementKey와 정확히 일치해야 하며 양쪽 승인은 제안 시각 이후, 예약 시각은 최신 만남일 자정과 같아야 한다. 예전 ID-only 동의 원본은 보존하되 새 공개 근거로 추정하지 않는다.
- 후보 원본의 동의된 관리자 화면 열람은 실제 보이는 탭에서 내부 대상 ID/가상 Owner/목적/프로필·선호 버전/시각만 중복 없이 감사 메모리에 기록한다. 사진·편지·비공개 이상형 원문과 전화번호를 로그에 넣지 않는다. 실제 서버 최소 권한·열람 감사·로그 불변성·보유기간은 미구현/검토 필요이며 효과 기반 가상 로그는 서버 보안 경계가 아니다.
- 장기 대기 화면은 기존 내 정보의 일시정지·내 요청 및 문의의 대기 지속·취소 상담으로 직접 연결한다. 새 정책·자동 취소·검토 완료를 생성하지 않는다.
- 모바일 360/390px 및 키보드·오류·줄바꿈 검사는 실제 실행한 범위만 보고한다. 한국어 페이지 언어를 지정하며 일반 화면 통과를 모든 상태/실기기/보조기술의 검증 완료로 확대하지 않는다.
- 360px 개발용 A 편지 시각 입력의 가로 넘침과 다크 모드 오류 글자/카드 대비 미달을 실제 검증에 따라 보완했다. 다크 오류 토큰은 더 밝게, 파괴적 작업 버튼의 글자는 별도 전경 토큰으로 구분하며 보라·파랑·Pretendard는 유지한다.

## 22 — 웹 개인 열람·유출 억제
- 상대 프로필은 최초 열람 안내 확인 후 표시하며 탭 메모리에서 회원별 한 번만 확인한다. 새로고침 시 초기화되며 실서비스는 서버 계정별 안내 버전 확인 기록을 사용한다. DOM 숨김만으로 권한 보안을 주장하지 않는다.
- 상대 사진에 BEFORE US · 개인 열람용 · 난수 내부 코드를 표시한다. 실명·전화번호·이메일은 포함하지 않는다. 현재 코드는 가상 회원과 탭 메모리에서만 연결하고 30초마다 얕게 위치를 바꾼다. 움직임 줄이기는 위치 변경을 멈춘다.
- 출시 전 서버가 인증된 열람 회원·세션과 연결하는 추측 어려운 코드를 발급하고 서버에서 워터마크를 이미지에 합성해야 한다. 클라이언트 오버레이는 제거 가능하므로 추적·유출 방지 보장이 아니다. 실제 사진은 공개 영구 URL이 아닌 매 요청 당사자·동의·사진 버전·중단/차단 확인과 짧은 만료 URL/인증 프록시, 캐시·재사용·만료/철회 접근 정책 검토가 필요하다.
- 다운로드 버튼은 제공하지 않는다. 드래그/우클릭/지원 브라우저 길게 누르기 저장 억제는 사진 영역에만 적용하는 보조 수단이며 키보드 접근·확인·문의는 유지한다. 브라우저/OS 스크린샷이나 다른 기기 촬영까지 완전히 막을 수 있다고 주장하지 않는다.
- Permissions-Policy의 display-capture는 사이트의 화면공유 API 사용을 제어할 뿐 OS 스크린샷 차단이 아니다. 이 변경에서는 해당 헤더를 캡처 차단 수단으로 추가하지 않는다.
- 연락처 DTO 제공 때 당사자·최신 약속·양쪽 별도 동의·당일 00:00·실제 가상 공개 이벤트·안전 조건을 재검사하고 복사 직전 최신 가상 상태도 검사한다. 공개 전 철회/취소의 예약 취소 규칙을 유지한다. 서버 인증·당사자 권한·로그인 세션/만료·조회/복사 엔드포인트 재검증은 미구현 개발 항목이다.
- 전화번호는 카카오 본문·URL·푸시·로그에 넣지 않는다. 열람 로그는 현재 코드/소개 ID/프로필 버전/최초 열람 시각만 중복 없이 탭 메모리에 최대 100개 기록한다. 회원 연결은 별도 가상 메모리 맵이며 외부/광고 분석으로 전송하지 않는다. 실제 로그 목적·최소 항목·접근 권한·보유기간은 출시 전 검토하고 임의로 확정하지 않는다.
- 모든 기능은 가상 자료 데모이며 워터마크·저장 억제를 보안 완료로 표현하지 않는다. 기존 가격·소개·A/B·약속·연락처 공개 예약 정책과 과거 기록은 보존한다.

## 21 — 지역·직업·운영진 직접 소개 보완
- STEP 01의 주 활동 지역은 시·도 + 시·군·구 필수다. 기존 self.province/self.area와 원답변은 보존하고 기존 생활권 답변에는 보완을 안내한다. 집·직장 주소·GPS는 받지 않는다. 시·군·구 입력 형식 검사는 실제 위치 인증이 아니다.
- STEP 03의 desired.regions(상대 주 활동 지역, 시·도 복수/선호 없음), desired.meetingRegions(실제 만남 가능 시·도 복수), desired.travelTime(30분 이내/60분/90분/상관없음)은 내 지역과 별도 저장한다. 기존 이동시간 답변은 변환하지 않고 보존한다.
- 상대 지역을 필수로 지정한 경우 기존 후보 비교/준비 게이트에서 양방향 확인한다. 선호를 자동 필수로 바꾸거나 실제 만남 지역·이동시간을 약속 합의로 취급하지 않는다.
- 선택 직업/직무는 self.work(넓은 분야) + self.workTitle(선택 직업명)이다. 회사명·직장 주소·소득은 기본 수집하지 않는다. 각각 상대 공개 기본 OFF, 운영자 참고는 본인의 수집·매칭 동의 범위에서만 가능하다. 미입력은 무직이 아니며 직업은 필수 필터로 추가하지 않는다.
- 공개 홈/진행 방식은 ‘자동 점수로 사람을 붙이지 않습니다.’와 운영진이 신청서·사진·외적인 취향·관계 기준·생활·대화 성향을 직접 살펴 최종 한 사람을 제안한다는 설명, 핵심 문구를 강조한다. 서비스 전체의 AI 미사용을 단정하지 않는다.
- 가격·소개·A/B·약속 로직과 과거 기록은 보존한다. 가상 지역·직무 예시만 사용하며 실제 수집·과금·발송·자동 공개·배포는 금지한다.

## 20 — 내 정보 · 운영 예외 연결
- 기존 공개 홈·STEP 01~04·사진·외적 취향·가격·A/B·약속/연락처 공개 조건을 보존한다. 내 정보 편집 링크는 기존 신청 컴포넌트의 해당 단계로 이어진다. 핵심/사진/공개 범위 변경은 기존 새 버전·재검토 규칙, 비공개 선호는 다음 소개 반영 규칙을 재사용한다.
- 내 정보는 본인 정책/구매 시점 제공 범위/저장된 동의·버전/소개 이력 요약/결제·환불 요청/알림/소개 정지·재개 요청/문의·신고/공개 철회·탈퇴·삭제 요청을 연결한다. 한 브라우저의 서로 다른 가상 계정 알림·요청·피드백을 분리하고 다른 계정의 비공개 정보를 회원 DTO로 제공하지 않는다. 실제 서버 인증·권한은 미구현이다.
- 소개 정지·마케팅 해제·정오 대기 알림 해제는 소개 이용 권리 소멸이 아니다. 실제 첫 A/B 개시만 기존 초기 소개 혜택 종료 근거다. 횟수 차감·추가 소개권·숨은 만료·강제 재구매를 만들지 않는다. 구매·동의 원본이 없으면 추정하지 않는다. 기존 구매 정책/가격/범위 스냅샷은 신규 정책에 자동 소급하지 않는다.

## 09 이후 보완 — 자기표현·성향/관계 취향
- 기존 STEP 01~04, 사진, 외적 취향, 공개 동의·버전·재검토, 가격·소개·A/B를 유지한다. 한 줄 소개 아래 선택 접이식 영역과 외적 취향 뒤의 성향·관계 취향만 추가한다.

- 선호 MBTI는 상관없어요를 우선 제안하지만 자동 선택하지 않는다. 특정 MBTI는 복수 선택, 상관없어요와 동시에 저장 불가. 선호 성향 최대 5개, 연애 중요 기준 최대 3개, 자유 설명 200자 이내. 전부 선택이며 추가 필수 조건에 포함하지 않는다.
- MBTI·자기소개·자기 태그·일상·관심사·질문 답변은 공개를 켠 항목만 공개 응답과 STEP 04 미리보기에 포함한다. 선택 공개는 기본 꺼짐. 모든 상대 선호는 운영자 참고용 비공개이며 상대 응답 객체에 포함하지 않는다.
- 운영자 원본의 values와 section 메타데이터로 10번 검토용 연결만 준비한다. 후보 검토·확정 기능은 이번에 만들지 않는다. 외적 취향·기본 조건·생활·대화 성향과 함께 참고하며 MBTI 조합·태그 개수·답변을 점수화하거나 사진·MBTI로 성격/궁합을 추론하지 않는다.
- 새 공개 자기표현 변경은 기존 프로필 버전·재검토 규칙, 비공개 선호 변경은 다음 소개 반영 규칙을 유지한다. 실제 정보 생성·수집·발송 없이 메모리 가상 자료로만 시연한다.

## STEP 04 — 제공 프로필·동의·접수
- 제목은 ‘상대에게 보일 내용을 확인해 주세요.’ 좌측 공개 편집·우측 제공용 미리보기, 공통 입력·선택 컴포넌트를 재사용한다.
- 공개 응답은 명시적 허용 목록으로 새 객체를 만들며 운영자 원본과 분리한다. 상대 미리보기 컴포넌트에는 공개 응답만 전달한다. 정확한 생년월일·연락처·확인 자료·선호·필수 조건·운영자 메모·보완 이력·거절 사유는 공개 응답에 포함하지 않는다. 화면만 숨기는 것으로 보호하지 않는다.
- 기본 공개는 활동용 이름·계산한 만 나이·넓은 생활권·관계 목적·한 줄 소개와 검토된 필수 사진 3장. 선택 사진은 공개를 선택하고 기준 확인된 사진만 제공한다. 키·생활·관심사·넓은 직무 분야·답변은 공개를 켠 항목만 제공하며 선택 공개는 기본 꺼짐이다.
- 본인 성별·체형·스타일 원답변은 현재 승인된 제공 항목에 포함되지 않으므로 중앙 정의에서 운영자 참고용으로 구분한다. 상대 공개 선택을 표시해 놓고 실제 제공 목록에서만 빠지는 불일치를 만들지 않는다.
- 전체 회원 게시물이 아닌 특정 소개 상대 제공 범위다. 필요한 공개에 동의하지 않으면 보류·철회하며 아직 제공하지 않는다.
- 수집·이용, 운영자 매칭 검토, 상대 제공 준비, 최종 공개 확인, 선택 마케팅, 선택 정오 알림을 각각 관리한다. 동의는 자동 체크하지 않는다. 연락처 공유·후기·홍보 사진 사용은 포함하지 않는다.
- 실제 제공 전 특정 상대·목적·공개 항목/버전·기간 안내와 별도 동의를 결합한다. 프로필 제공 준비는 최종 호감 선택이 아니다. 정책의 제공·보유 기간은 검토 중이며 현재 제공 준비/정오 공개 게이트는 차단 상태다. 실제 서버 권한·저장 보안·법률 검토가 완료됐다고 주장하지 않는다.
- 신청 제출은 필수 정보·필수 사진 등록과 본인 확인 진술·필요 동의를 검사하며 사진 기준 확인/본인 인증/소개 준비 완료를 뜻하지 않는다. 선택 문항 미작성은 막지 않는다. 오류는 실제 누락 단계·공개 체크·동의로 이동한다.
- 완료 문구: ‘소개 신청을 받았어요.’ / ‘내용을 살펴보고, 소개 가능한 상대가 준비되면 안내드리겠습니다.’ 명확한 가상 접수 배지를 함께 제공한다. 계정·접수·사진 확인·본인 확인·소개 준비 상태는 분리한다.
- 사진·핵심 프로필·공개 변경은 새 버전과 재검토. 진행 제안의 승인 스냅샷을 덮어쓰지 않으며 상대 재확인·진행 보류를 검토한다. 비공개 선호는 별도 버전으로 다음 소개에 반영하며 현재 교류를 자동 종료하지 않는다.
- 사진 삭제·공개/필수 동의 철회·신청 보류/철회는 새 제안 중단과 기존 접근 재검토 상태에 연결한다. 이미 본 화면·캡처 회수는 보장하지 않는다. 동의 재개는 본인이 직접 선택한다.
- 모든 원본·접수·제공 준비는 메모리 가상 자료 데모다. 실제 개인정보 수집·제공·발송·결제·배포는 하지 않는다. 실제 구현 시 공개 allowlist와 특정 상대별 접근 검사는 서버에서 수행해야 한다.

## STEP 03 — 기본 조건·함께할 방식
- 탭은 기본 조건 / 외적인 취향 / 함께할 방식. 기본 조건·함께할 방식에 이어 승인된 외적인 취향 입력을 추가한다.
- 자기진술 self.*와 상대 선호 desired.*는 별도 저장한다. 모든 선호는 상대 비공개이며 매칭 동의 후 운영자 참고와 공개 동의는 구분한다.
- 미입력·선호 없음·비공개 응답 표시는 별도다. 비공개 응답 표시는 실제 값을 선호 없음으로 바꾸지 않는다. 표시 여부와 무관하게 상대 공개를 허용하지 않는다.
- 나이 최소·최대는 성인 기준 이상의 정수, 최소≤최대, 경계 포함이다. 선호 없음과 상세 조건은 동시 선택·저장 불가다.
- 추가 필수 조건 최대 3개는 운영 초안 설정값. 나이·지역·관계 목적·흡연·키만 비교 가능하다. 공통 성인·상호 소개 대상·활동 상태 조건은 개수에서 제외한다.
- 기본 중요도는 선호. 주관적인 인상·스타일·대화 느낌은 자동 탈락 조건이 아니다. 운영자가 필수 기준을 자동 완화하지 않는다.
- 상대 정보가 없으면 확인 필요. ‘아직 정리 중’과 ‘진지한 연애’를 동일 취급하지 않는다. 계산하지 않은 후보 수·확률·대기일은 노출하지 않는다.
- 대화 성향 최대 3개, 관심사 최대 5개. A/B는 설명만 제공하고 상호 선택·양쪽 결제 뒤 두 사람이 방식과 시작일을 합의한다.
- 추가 기준 요청·신청 보류 의사는 데모 초안 메모리에서만 관리한다. 실제 운영자 발송·신청 보류 처리·민감정보 저장은 구현하지 않는다.

## STEP 03 — 외적인 취향 추가
- 전체 선택 사항. 기본 취향과 상세 취향은 별도로 접고 펼친다. 미입력·선호 없음·나중에 작성은 구분한다. 기존 상세 답변에서 선호 없음·나중에 작성으로 전환하면 사용자가 삭제를 확인한 뒤 외적 답변과 키 필수 조건만 지운다.
- 원하는 외적 선호는 desired.appearance.*에 중앙 정의하며 self.*와 별도다. 인상·스타일 최대 3개, 체형 최대 2개. 키는 양의 정수 cm 최소≤최대, 경계 포함이며 추가 필수 조건 3개 한도에 함께 센다.
- 헤어·눈매·안경·수염과 200자 이내 자유 설명은 선택이다. 성별에 따라 답변을 강제하지 않는다. 체중·BMI·신체 치수·피부색·인종·시술·건강 항목은 만들지 않는다.
- 사진 업로드·닮은꼴 검색·AI 매력 점수는 만들지 않는다. 태그는 신청자의 비공개 설명이며 다른 회원 사진에 자동 라벨·외모 등급·성격·인종·성별·신원 판정을 붙이지 않는다.
- 운영자는 사진과 양쪽 외적 선호·관계·생활 기준을 함께 참고한다. 주관적 느낌을 필수 점수로 바꾸거나 자동 합산 점수만으로 상대를 확정하지 않는다. 태그 개수에 따른 정확도·우선 소개를 약속하지 않는다.
- 요약은 실제 선택값만 사용한다. 미입력은 추측하지 않는다. 상대 공개 projection에는 외적 선호를 포함하지 않는다. 홈·알림·후기·외부 광고 분석에 전달하지 않는다. 현재 초안은 메모리 데모이며 실제 민감정보 저장·발송은 하지 않는다.
- ‘끌리는 사람’은 특정 외모 등급을 뜻하지 않는다. 외모 비하·타인 개인정보 입력을 피하도록 안내한다.

## 05 — 계정과 4단계 소개 신청 · STEP 01
- 기존 로그인 수단을 유지한다. 현재 실제 인증·계정 생성은 연결되어 있지 않으며 이를 연결된 기능처럼 표시하거나 새 로그인 업체를 임의로 추가하지 않는다. 계정 단계에서 사진·이상형은 필수가 아니다.
- 소개 신청은 나에 대해 / 사진 / 원하는 만남 / 공개·동의 확인의 4단계다. 현재 사진은 가상 파일·도형 구도 예시만 사용하며 실제 사진·신분증은 수집하지 않는다. 최신 승인된 STEP 02의 필수 3장·선택 1장 규칙을 따른다.
- 필드 형식·목적·필수 여부·공개 범위·검사 규칙은 src/app/application-model.ts에서 관리한다. 진행률은 필수 항목 기준으로 계산하며 미작성 선택 항목은 미완성 처리하지 않는다. 입력한 선택 항목에는 형식과 최대 선택 수 규칙을 적용한다.
- 활동용 이름 2~12자와 연락처·SNS 삽입 금지, 한 줄 소개 20~150자, 선택 대화 질문 1개와 답변 50~300자를 검사한다.
- 기존 인증 나이·생년월일 값을 사용할 수 있으면 중복 입력받지 않는다. 자기 입력에서 계산된 나이를 인증 완료로 표시하지 않는다. 원 생년월일은 비공개이며 상대에게는 공개 동의한 만 나이만 표시한다.
- 만 19세 이상 및 기본 이성 소개는 운영 초안 설정이다. 사진에서 성별·지향을 추론하지 않으며 본인 성별과 소개받을 상대 조건은 별도 필드로 본인이 확인한다.
- 시·도와 넓은 생활권만 입력한다. 집·직장 주소·GPS는 금지한다. 현재 다른 사람과 교제·혼인 관계가 없고 성실히 참여할 의사가 있다는 값은 본인 진술이며 미혼 인증이 아니다.
- 선택 항목은 키 직접 입력·체형·스타일 최대 3개·흡연·음주·생활·편한 시간·관심사 최대 5개·넓은 직무 분야·대화 질문과 답변이다. 직장명·학벌·소득·재산·건강·정치·상세 연애 이력은 추가하지 않는다.
- 미입력·선호 없음·답변 거절·답했지만 상대 비공개를 구분한다. 선택 정보의 상대 공개는 기본 꺼짐이다. 매칭 목적의 운영자 참고 동의와 상대 공개 선택을 별도로 관리한다. 나의 정보는 원하는 상대 조건으로 복사하지 않는다.
- 핵심 항목과 접을 수 있는 선택 항목을 분리한다. 이전·수정 이동·임시 저장·이어서 작성을 제공한다. 실제 접수는 하지 않으며 마지막 확인도 가상 신청 확인으로 표시한다.
- 임시 저장은 현재 브라우저 탭의 모듈 메모리에서만 유지한다. 서버·localStorage·sessionStorage에 민감정보를 저장하지 않는다. 다른 화면에서 돌아와 이어 쓸 수 있으나 새로고침·탭 종료 시 삭제됨을 명시한다.
- 회원 오늘의 이어쓰기는 실제 운영자 검토를 가장하지 않고 저장된 데모 작성 단계로 연결한다. 가상 작성 완료는 실제 접수·검토 대기로 자동 전환하지 않는다.

## 06 — STEP 02 사진
- 제목은 “현재의 나를 보여 주세요.”, 안내는 “특별히 촬영한 사진일 필요는 없어요. 최근의 모습을 솔직하게 보여 주세요.”를 유지한다.
- 슬롯 정의·형식·권리·자기확인·검토·제안 스냅샷은 src/app/photo-model.ts, 화면은 src/app/PhotoStep.tsx, 필수 진행률·최종 공개 확인은 신청 모델에 연결한다.
- 필수 3장: 대표 얼굴 / 자연스러운 상반신 / 전체 스타일. 선택 1장: 본인이 나온 취향·일상. 최대 4장이다. 최근 3개월 이내 서로 다른 사진은 운영 초안 설정이며 촬영일·현재 모습은 본인 자기확인이다.
- 얼굴은 혼자·정면 또는 가까운 구도로 또렷하게, 마스크·선글라스·과한 보정 없이. 상반신은 일상의 표정·분위기이며 대표 사진의 단순 확대·복제는 불가. 전체 스타일은 평소 옷차림으로 확인하며 노출·속옷·치수 인증을 요구하지 않는다.
- 제공 권리가 있는 사진만 사용하도록 안내한다. AI 생성 인물·타인 사진·과도한 얼굴/체형 변형·단체 사진·식별되는 제3자·주소·연락처 포함을 피하도록 안내한다. 예시는 도형·구도 설명만 사용하며 실존 인물 사진을 가져오지 않는다.
- 슬롯별 가상 등록·교체·삭제·미리보기·실패·재시도를 지원한다. 목록 자르기 예시와 전체 원본 비율을 구분하고 원본 정보는 자르기 토글로 바꾸지 않는다. 자동 미용 보정·몸 측정은 없다.
- JPG/JPEG·PNG·WebP, 장당 10MB 이하, 짧은 변 800px 이상 권장. 권장 크기는 필수 제출 규칙으로 바꾸지 않는다. HEIC 변환은 연결되어 있지 않으므로 지원하지 않고 변환 안내만 한다.
- 검토 상태: 대기 / 기준 확인 / 재등록 요청. 사유: 얼굴 확인 어려움 / 동일 사진 / 흐림 / 타인 등장 / 현재 모습 재등록 필요. 문제 슬롯만 재등록하고 나머지 사진·신청 내용은 보존한다. 외모 점수나 미달 표현은 사용하지 않는다.
- 필수 3장과 자기확인으로 데모 제출 가능하나 승인 완료는 아니다. 기준 확인은 외모·인성·안전 인증이 아니다. 별도 외적인 큐레이션은 공개된 기준·절차로 분리한다.
- 교체 사진은 자기확인과 검토를 다시 거친다. 교체·삭제는 활성 제안의 승인 사진을 자동 변경하지 않는다. 활성 제안 사진은 버전별 스냅샷으로 별도 보존하며 초안 공개 선택도 실제 제안 공개를 변경하지 않는다.
- 최종 공개·동의 단계에서 사진별 상대 공개 선택과 사진 초안을 다시 확인한다. 가상 파일·대기 검토를 실제 공개나 승인으로 표시하지 않는다.
- /demo/photos의 검토·보완·활성 제안 전환은 분리된 개발용 가상 시연이다. 신청 화면에는 운영자 검토 전환 도구를 노출하지 않는다.
- 실제 개발 항목(현재 미구현): 서버 실형식·용량·디코딩 검사, 회전 정상화·재인코딩·GPS 등 메타데이터 제거, 안전한 실제 업로드·저장·접근제어, 승인 사진 공개의 명시적 갱신 절차. 가상 파일의 선언된 메타데이터 검사나 도형 렌더링으로 보안 구현 완료를 주장하지 않는다.
