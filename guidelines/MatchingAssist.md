# 후보 추천 보조 · 성비 · 신뢰 장치

모두 가상 자료 데모이며 실제 인증 업체·서버·외부 AI는 연결하지 않았다.

## 후보 추천 1단계 — `match-recommendation.ts`, `MatchingAssist.tsx` (/admin/matching → 02 양쪽 조건)

1. 제외: 같은 성별·상호 소개 대상 아님, 양방향 필수 조건 미충족, 차단, 이전 소개 상대, 일시정지·탈퇴, 다른 소개·교류 진행, 다른 후보 준비 중, 성비 대기, 신청 접수 전. 제외 사유는 운영자가 펼쳐 볼 수 있다.
2. 이유(근거 인용 필수):
   - 같은 답: 관계 목적, 쉬는 날, 관심사, 알아갈 때 중요하게 보는 것, 생활 리듬
   - 한쪽이 바라는 것 ↔ 다른 쪽 답: 선호하는 모습↔나를 설명하는 모습, 연애 기준↔중요하게 보는 것(생활 패턴=생활 리듬, 취미 공유=취향 공유), 원하는 관심사, 시간대, 음주, 실제 만남 가능 지역
3. 주의: 미입력 항목(추측하지 않음), 생활 시간대 차이, 만남 가능 지역 밖, 필수 조건 ‘확인 필요’, 인증값 없음.
4. 정렬: 만남 가능 지역 안 → 근거 가중치(양쪽 모두 바라는 점이 있으면 가산). 가중치는 화면에 넘기지 않는다. 최대 5명.
5. 기록: 추천 표시 목록과 운영자 최종 선택(목록 안/밖)을 함께 남긴다. 다음 단계의 추천 품질 검증 자료다.

쓰지 않는 정보: 사진, 외적인 취향, MBTI, 체형·스타일, 직업.

## 성비 — `gender-balance.ts` (관리자 대시보드)

| 상태 | 기준 | 동작 |
| --- | --- | --- |
| 기준 이내 | 60% 이하 | — |
| 경보 | 60% 초과 | 대시보드 경고, 부족한 쪽 모집 안내 |
| 대기열 | 70% 이상 | 많은 쪽 성별 새 신청을 순차 검토 대기로 접수 |
| 판단 보류 | 표본 10명 미만 | 비율 판단 안 함 |

- 전체와 같은 지역·연령대 묶음(10명 이상)을 각각 판단.
- 대기 해제: 오래 기다린 순서, 해제 후 70% 넘으면 사유 필수.
- 회원 화면: ‘신청이 많아 순서대로 검토 중’만 표시. 숫자·비율 비노출.

## 신뢰 장치

- 본인·성인 인증 (`identity-model.ts`): 가상 결과 4종(성인/미성년/실패/이전 제한 계정과 동일). 인증 전 신청 접수 불가.
- 기혼·교제 고지 확인 (`self.pledge`) 필수, 신고 유형 ‘기혼·교제 중 의심’ 우선 확인.
- 첫 만남 안전 가이드 7항목, 만남 후 피드백 (`meeting-aftercare.ts`): 시작 60분 뒤, 1회, 운영진 전용, 불참→노쇼 안내, 안전 확인 요청→신고 접수. 관리자 후기 화면에 쌍 요약.
- 대기 단계·프로필 코칭 (`member-guidance.ts`): /today, /profile.
