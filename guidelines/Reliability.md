# 오류 알림·백업 체계 (2026-10-15)

## 1. 오류 알림 — 지금 들어가 있는 것

| 장치 | 위치 | 하는 일 |
|---|---|---|
| 화면 오류 안내 | `src/app/RouteError.tsx` (공개·회원·관리자 라우트의 errorElement) | 흰 화면 대신 "문제가 생겼어요 / 새로고침 / 홈 / 문의" 안내. 배포 직후 예전 화면 조각을 못 불러오면 "새 버전이 준비됐어요"로 새로고침을 권한다 |
| 오류 보고 | `src/app/error-report.ts` `reportError()` | 오류를 한 곳으로 모은다. 같은 오류는 한 번만 보낸다. 이메일·전화번호 모양 문자열은 지우고, 주소의 쿼리·해시는 보내지 않는다 |
| 화면 밖 오류 | `installGlobalErrorReporting()` (`src/main.tsx`에서 시작) | `window.error`, `unhandledrejection`도 보고한다 |

**알림을 실제로 받으려면(서버 단계)**
1. Vercel 환경변수 `VITE_ERROR_ENDPOINT`에 수신 주소를 넣는다. 둘 중 하나를 고른다.
   - Sentry DSN을 받는 작은 서버 함수
   - Supabase Edge Function → 슬랙·이메일로 전달
   - 설정하지 않으면 지금처럼 브라우저 콘솔에만 남는다.
2. `VITE_RELEASE`에 배포 버전(커밋 해시)을 넣어, 어느 배포에서 난 오류인지 구분한다.
3. 같은 오류가 10분 안에 5번 이상 오거나 결제·공개 작업 실패가 생기면 슬랙으로 즉시 알린다. 나머지는 매일 아침 요약한다.

**서버 쪽 오류(2026-10-16 반영)**
- 정오 공개·응답 마감·보존 기간 정리는 `job_runs`에 성공·실패를 남기고, 운영진 대시보드 ‘예약 작업 기록’에 보인다. 정오 작업은 12:05에 한 번 더 돌아 실패를 메운다(같은 일을 두 번 하지 않음).
- 지운 사진 파일은 `storage_cleanup` 대기열 → `storage-cleanup` 함수(매일 04:00 KST)가 지운다. 열람 기간인 소개 사본에 쓰이는 사진은 남긴다.

**서버 쪽 오류(남은 일)**
- 정오 공개, 결제 기한 처리, 연락처 자정 공개, 알림 발송 같은 **예약 작업마다 성공·실패를 기록**한다. 실패하면 즉시 알린다(사람이 다시 실행할 수 있도록).
- 외부 상태 확인: 무료 업타임 모니터(예: UptimeRobot)로 홈과 상태 확인 주소를 5분마다 확인한다.

## 2. 데이터 백업 — 서버 단계 계획

지금은 데모라 저장되는 데이터가 없다. Supabase로 옮긴 뒤 아래를 적용한다.

| 항목 | 방식 | 보관 |
|---|---|---|
| 데이터베이스 | Supabase 일일 자동 백업 + **PITR(특정 시점 복구)** (Pro 요금제) | 7일(PITR), 일일 백업은 요금제 기준 |
| 별도 사본 | 주 1회 `pg_dump` 암호화 파일을 다른 저장소에 보관(다른 리전 또는 다른 서비스) | 최대 30일. 개인정보 기준(백업 30일 안 파기)과 맞춘다 |
| 사진 파일 | Supabase Storage 버킷 버전 관리. 탈퇴·삭제 시 원본과 사본을 함께 지운다 | 개인정보 기준 그대로 |
| 설정·코드 | GitHub(이미 운영 중), 저장 태그로 화면 되돌림 지점 관리 | 계속 |

**복구 훈련:** 월 1회 테스트 환경에 최근 백업을 복구해 본다. 걸린 시간과 문제를 기록한다.

**탈퇴와 백업의 관계:**
- 탈퇴한 회원의 자료는 운영 DB에서 7일 안에 지운다.
- 백업에 남은 사본은 30일이 지나면 백업과 함께 사라진다.
- 백업에서 복구할 때는 이미 탈퇴한 회원의 자료를 다시 지우는 단계를 반드시 거친다.

## 3. 계정(로그인) — 지금과 서버 단계

- 지금: `src/app/auth-service.ts`(탭 메모리 데모)
  - 회원가입: 이메일, 비밀번호 8자 이상에 영문·숫자 포함, 만 19세·약관·개인정보 동의
  - 로그인: 없는 계정과 틀린 비밀번호를 같은 문구로 안내, 5번 틀리면 5분 잠금
  - 비밀번호 재설정: 가입 여부와 관계없이 같은 안내, 30분짜리 1회용 링크, 바꾸면 다른 로그인 종료
  - 탈퇴: 비밀번호 재확인 → 탈퇴 요청 기록 → 즉시 로그아웃, 7일 안 삭제 안내
- 서버 단계: 함수 이름과 모양은 그대로 두고 내부를 Supabase Auth로 바꾼다.
  - `signUp` → `auth.signUp`
  - `signIn` → `auth.signInWithPassword`
  - `requestPasswordReset` → `auth.resetPasswordForEmail`
  - `resetPassword` → `auth.updateUser`
  - `withdraw` → 서버 함수로 탈퇴 요청과 세션 종료
  - 비밀번호 해시는 Supabase가 bcrypt로 처리한다.
